# Развёртывание на сервере заказчика

Эта инструкция создаёт отдельную установку без токенов, IP-адресов и ADB-ключей
других организаций. Для каждого заказчика используются отдельный Telegram-бот,
конфигурация и каталог проекта.

## Что запросить у заказчика

- SSH-доступ к Linux-серверу с `sudo` либо заранее установленным Docker;
- часовой пояс объекта в формате IANA, например `Asia/Almaty`;
- Telegram ID сотрудников, которым разрешено управление;
- модель, IP, ADB-порт, MAC и HTTPS-страницу каждого телевизора;
- подтверждение, что сервер видит ADB-порты телевизоров;
- отдельного бота, созданного организацией через `@BotFather`.

Токен бота не нужно отправлять в переписке или добавлять в Git. Его вводят
скрыто непосредственно на сервере заказчика.

## Требования к серверу

- актуальный Linux x86_64 или arm64;
- Docker Engine и плагин Docker Compose;
- Git и Python 3 для установки и обслуживания;
- исходящий HTTPS-доступ к Telegram API;
- маршрут до сети телевизоров;
- не менее 1 ГБ свободной памяти и 2 ГБ диска;
- синхронизация времени через NTP.

ADB-порты телевизоров разрешаются только от управляющего сервера. Публиковать
порт `5555` в Интернет запрещено.

## 1. Скопировать проект

Пример установки в домашний каталог технического пользователя:

```bash
mkdir -p "$HOME/docker"
cd "$HOME/docker"
git clone <REPOSITORY_URL> tv-telegram-control
cd tv-telegram-control
```

Для коммерческой установки рекомендуется отдельный Linux-пользователь, который
входит в группу `docker` и не используется сотрудниками для обычной работы.

## 2. Создать конфигурацию заказчика

Команда не перезаписывает существующие `.env` или `data/config.json`. Telegram
токен запрашивается скрыто и сохраняется с правами `600`.

```bash
python3 scripts/init_installation.py \
  --telegram-user-id 123456789 \
  --tv-name "Телевизор в зале" \
  --tv-ip 192.168.10.50 \
  --tv-port 5555 \
  --tv-mac AA:BB:CC:DD:EE:FF \
  --tv-url https://example.org/tv \
  --timezone Asia/Almaty
```

Для нескольких администраторов повторите аргумент `--telegram-user-id`. Остальные
телевизоры безопаснее добавить через интерфейс Telegram после запуска либо
внести в `data/config.json` до проверки.

## 3. Проверить и запустить

```bash
docker compose config --quiet
docker compose build
docker compose run --rm tv-telegram-control \
  python3 /app/tv_bot.py --check-config
docker compose up -d
docker compose ps
docker compose logs --tail=100
```

Контейнер должен перейти в состояние `healthy`. Если ADB показывает
`unauthorized`, подтвердите RSA-ключ на экране телевизора и выберите постоянное
разрешение:

```bash
docker compose exec tv-telegram-control adb devices -l
```

## 4. Приёмочная проверка

1. Отправить `/start` с разрешённого Telegram-аккаунта.
2. Убедиться, что посторонний аккаунт не получает меню управления.
3. Проверить Home, D-pad, звук, открытие страницы и скриншот.
4. Проверить ожидание и пробуждение через 15 минут.
5. Перезапустить контейнер и убедиться, что ADB-авторизация сохранилась.
6. Проверить расписание в часовом поясе объекта.
7. Заполнить протокол совместимости и техническое заключение.

## 5. Резервная копия

```bash
./scripts/backup.sh
```

Копия содержит конфигурацию, Telegram-токен и приватный ADB-ключ, поэтому каталог
резервной копии имеет права `700` и должен храниться в защищённом месте. Для
восстановления остановите контейнер и верните каталоги `data/`, `secrets/`,
`adb/` и файл `.env` в корень проекта.

## 6. Последующие обновления

С рабочей станции исполнителя задайте цель явно:

```bash
export TV_BOT_DEPLOY_TARGET=admin@10.0.0.10
export TV_BOT_REMOTE_DIR=/home/admin/docker/tv-telegram-control
./scripts/deploy.sh
```

Скрипт отказывается работать без обоих параметров, запускает тесты, создаёт
резервную копию, проверяет конфигурацию, ждёт `healthy` и при ошибке возвращает
предыдущий образ и файлы.

## Передача заказчику

- заказчик владеет Telegram-ботом и токеном;
- перечислены допущенные Telegram ID;
- переданы адрес проекта и инструкция резервного копирования;
- зафиксированы модели телевизоров, прошивки и известные ограничения;
- назначен ответственный с физическим доступом к экранам;
- согласовано, кто устанавливает обновления ОС телевизоров и сервера;
- проверено, что секреты и ADB-ключи отсутствуют в Git.
