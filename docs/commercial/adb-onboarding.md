# Подготовка телевизора и подключение ADB

Инструкция выполняется сотрудником клиента вместе со специалистом по
подключению. Названия пунктов меню отличаются у производителей.

## 1. Подготовить сеть

1. Подключить телевизор и сервер к одной доверенной сети.
2. Назначить телевизору постоянный адрес через DHCP reservation.
3. Запретить доступ к ADB из Интернета и гостевых VLAN.
4. Записать IP и MAC-адрес телевизора.

## 2. Включить параметры разработчика

Обычно необходимо открыть «Настройки → Об устройстве» и несколько раз нажать на
номер сборки. Затем включить один из вариантов:

- «Отладка по сети» / Network debugging;
- «ADB debugging»;
- «Беспроводная отладка» / Wireless debugging.

На Fire TV путь и название меню отличаются. Следует использовать официальную
[инструкцию Amazon](https://developer.amazon.com/docs/fire-tv/developer-tools.html).

## 3. Определить тип подключения

### Классический TCP ADB

Часто используется постоянный порт `5555`:

```bash
adb connect <TV_IP>:5555
adb -s <TV_IP>:5555 get-state
```

На экране телевизора нужно подтвердить RSA-ключ и выбрать «Всегда разрешать».

### Wireless debugging с pairing-кодом

Android 11 и новее может показывать отдельный pairing-порт и временный код:

```bash
adb pair <TV_IP>:<PAIRING_PORT>
adb connect <TV_IP>:<ADB_PORT>
adb -s <TV_IP>:<ADB_PORT> get-state
```

Pairing и рабочий ADB-порт могут отличаться. Официальное описание находится в
[документации Android](https://developer.android.com/studio/run/device.html).

## 4. Получить профиль устройства

Команды не должны изменять настройки телевизора:

```bash
adb -s <ADDRESS> shell getprop ro.product.manufacturer
adb -s <ADDRESS> shell getprop ro.product.model
adb -s <ADDRESS> shell getprop ro.build.version.release
adb -s <ADDRESS> shell getprop ro.build.fingerprint
```

В отчёте fingerprint можно хранить частично. Серийный номер публиковать не
нужно.

## 5. Проверить сохранение доступа

1. Отключиться и подключиться повторно.
2. Перезагрузить телевизор только с разрешения клиента.
3. Повторить `adb connect` и `get-state`.
4. Перевести телевизор в ожидание на 10–15 минут.
5. Проверить, остаётся ли ADB-порт доступным и возможно ли пробуждение.

Если после каждого запуска требуется физическое подтверждение, устройство не
подходит для штатной эксплуатации.

## 6. Зафиксировать результат

Результат переносится в реестр совместимости и клиентское заключение. Сам факт
успешного `adb connect` ещё не означает полной совместимости: отдельно проверяют
питание, браузер, звук, скриншоты и восстановление связи.
